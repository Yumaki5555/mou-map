# データの追加方法（MOUを1件追加・修正するとき）

このサイトのMOUデータは、HTMLの中ではなく `data/mous/` フォルダの **JSONファイル**（データを書くための決まった書式の文字ファイル）に入っています。
ファイルを書き換えて保存し、GitHubに上げ直すと、地図の色・件数・グラフ・一覧が**自動で**新しくなります。

---

## 1. どのファイルに書くか

| 何のMOUか | ファイル |
|---|---|
| 都道府県のMOU | `data/mous/pref-都道府県コード.json`（例：茨城県 → `pref-08.json`） |
| 国・省庁のMOU | `data/mous/national.json` |
| 市区町村（政令指定都市など）のMOU | `data/mous/city-市区町村コード.json`（例：横浜市 → `city-141003.json`） |
| 団体・企業・公的機関などのMOU | `data/mous/orgs.json`（10を参照） |

- 都道府県コードは北海道＝01 〜 沖縄県＝47 です（`data/prefectures.json` に一覧があります）。
- **ファイルがまだない県**に追加するときは、ほかの県のファイルをコピーして名前を変え、中身を入れ替えます。そして `data/mous/index.json` の `"files"` の一覧にファイル名を1行追加してください（追加しないと読み込まれません）。

## 2. 書き方（1件分のひな形）

`tools/template_mou.json` が1件分のひな形です。これをコピーして、ファイルの `"mous": [ ... ]` の中に追加します。
件と件の間は **`,`（半角カンマ）** で区切ります。最後の1件のあとにはカンマを付けません。

### 必ず入れる項目

| 項目 | 意味 | 書き方の例 |
|---|---|---|
| `id` | 固有の番号。**一度決めたら変えない** | `"JP-08-010"`（県コード＋連番）。国は `"JP-NAT-046"` |
| `title_ja` | 協定の正式名称 | 正式名称が分からないときは公式発表の表現を書き、`notes` に「正式名称未確認」 |
| `doc_type` | 文書の種類 | `"MOU"` `"MOC"` `"覚書"` `"了解覚書"` `"協力覚書"` `"その他の協力文書"` |
| `japan_level` | 日本側の区分 | 国＝`"national"`、都道府県＝`"prefecture"`、市区町村＝`"municipality"` |
| `pref_code` | 都道府県コード | `"08"`（国のときは `null`） |
| `country_code` | 相手国のコード | `"VN"`（ベトナム）など。`data/countries.json` にある2文字のコード |
| `partner_org` / `partner_type` | 相手機関と、その種類 | 種類は下の表を参照 |
| `signed_date` | **締結日**（発表日ではない） | `"2026-10-01"`。月までしか分からなければ `"2026-10"` |
| `fields` | 分野（複数可・主な分野を先頭に） | `["labor"]`、`["economy", "tourism"]` |
| `status` | 実施状況 | 下の表を参照 |
| `sources` | 情報源（**1件以上必須**） | 題名・発行元・URL・確認日を書く |

### 相手機関の種類（`partner_type`）

| 書く値 | 意味 |
|---|---|
| `national_gov` | 国そのもの（政府全体） |
| `national_ministry` | 中央省庁・その部局 |
| `subnational_gov` | 州・省・県など地方政府 |
| `public_agency` | 公的機関 |
| `university` | 大学・学校 |
| `organization` | 団体 |
| `company` | 企業 |
| `international_org` | 国際機関（`country_code` は `"ZZ"`） |

### 分野（`fields`）

`labor`＝外国人材・労働、`economy`＝経済・投資・企業誘致、`education`＝教育・留学・研究、`medical`＝医療・福祉、`tourism`＝観光・文化、`agri`＝農業・水産業、`disaster_env`＝防災・環境・技術、`other`＝その他

### 実施状況（`status`）

| 書く値 | 画面の表示 | 使うとき |
|---|---|---|
| `signed` | 締結済み | 締結は確認できたが、具体的な事業はまだ確認できていない |
| `in_progress` | 具体的な事業が実施中 | 人材の受入れ・研修などが行われていると公式資料で確認できた |
| `completed` | 完了 | 事業が終わったと確認できた |
| `expired` | 期限満了・終了 | 有効期間が終わった・終了したと確認できた |
| `unknown` | 実施状況未確認 | 締結後のようすが分からない |
| `planned` | 締結予定（件数に含めない） | 「締結します」という予定の発表しかない |

### 法的拘束力（`legal_binding`）

`not_binding`＝文書に「法的拘束力はない」と明記／`binding`＝拘束力ありと明記／`not_stated`＝原文を読んだが書いていない／`unconfirmed`＝原文を確認できていない

### 確認の根拠（`evidence_level`）

`original_text`＝協定の原文で確認／`official_announcement`＝公式発表で確認／`official_list`＝公式の一覧で確認／`assembly`＝議会資料で確認／`partner_official`＝相手国側の公式発表で確認／`news_only`＝報道のみ（**初期設定では件数に入りません**）

## 3. 予算と「地域への影響」の書き方

予算と影響には、**必ず根拠の資料（`sources` の id）と対象年度**を付けます。

```json
"budgets": [
  {
    "fiscal_year": "2025",
    "kind": "planned",
    "amount_yen": 19950000,
    "original_text": "19,950千円",
    "payer": "prefecture",
    "item": "外国人材確保支援事業",
    "relation": "MOU関連事業の当初予算（MOU自体の予算ではない）",
    "sources": ["s2"]
  }
],
"impacts": [
  {
    "category": "population",
    "stage": "implemented",
    "text": "2025年度にMOUに基づき12人が県内企業に就職（県発表）",
    "value": 12,
    "unit": "人",
    "fiscal_year": "2025",
    "causality": "stated_by_gov",
    "sources": ["s3"]
  }
]
```

- `kind`：`planned`＝計画予算、`settled`＝決算額（実際に使った額）、`subsidy`＝補助金
- `payer`：`national`＝国、`prefecture`＝都道府県、`municipal`＝市町村、`private`＝民間、`mixed`＝複数、`unknown`＝不明
- `amount_yen`：**円**で書く（千円の資料なら1,000倍）。**金額が分からないときは `null`**（`0` と書くと「0円」と表示されてしまいます）
- `category`（影響の分野）：`population`＝人口・外国人受入れ、`employment`＝雇用・地域経済、`housing`＝住宅・生活環境、`welfare`＝教育・医療・福祉、`fiscal`＝税金・財政、`community`＝住民生活・地域社会
- `stage`（段階）：`agreed`＝合意した内容、`implemented`＝実際に行われたこと、`observed`＝地域で確認された変化
- `causality`（MOUとの関係）：`stated_by_gov`＝行政資料がMOUの成果だと書いている、`unconfirmed`＝関連性は未確認

## 4. 更新・再締結の書き方（二重に数えないために）

同じ協定を更新・再締結したときは、**新しい1件として追加**し、次の2つを入れます。

- `group_key`：元の協定と**同じ値**にする（これで件数は1件のまま）
- `renewal_of`：元の協定の `id`

## 5. 書いたあとの確認（大事）

1. サイトを開き、上のメニューの **「資料・出典」→「データのダウンロード（CSV）・点検」** を押します（アドレスは #/data）。
2. 「データ点検」に **「誤りは見つかりませんでした」** と出ればOKです。誤りがあれば、ファイル名・ID・内容が表に出るので直してください。
3. 書き方を間違えたファイル（カンマ忘れなど）は読み込まれず、「データ点検」に「書き方に誤りがあります」と表示されます。ほかのファイルは表示され続けます。
4. 出典URLが開けるかは、次のコマンドで確認できます（mou-map フォルダで実行）。「リンク切れ：0件」になるまで直してから公開してください。

```bash
python tools/check_links.py
```

5. **公開用の索引を作り直します**（mou-map フォルダで実行）。サイトの最初の画面・地図・一覧は、元のデータから作った軽い索引（`data/build/core.json`）で表示しているため、これを実行しないと地図と一覧に反映されません。書き換わった `data/build/core.json`・`data/build/geo.json`・`index.html` も、元のデータと一緒にコミット・公開してください。

```bash
node tools/build_data.mjs
```

6. 最後に `node tools/test_site.mjs` を実行し、「不合格：0件」を確かめます（索引の作り直し忘れもここで見つかります）。

### リンク切れを見つけたとき

役所のサイトは改修のたびにページの場所（URL）が変わります。リンク切れの出典は、次の順で直します。

1. **新しい場所を探す**：同じ資料が発行元のサイトの別の場所に移っていないか探し、見つかったら `url` をそのURLに書き換えます。
2. **保存版にリンクする**：発行元のサイトから削除されていたら、国立国会図書館の **WARP**（https://warp.ndl.go.jp/ 。官公庁のサイトを保存している公的なサービス）か、**インターネットアーカイブ**（https://web.archive.org/ ）に残っている保存版を探します。保存版の中身が同じ資料であることを確かめたうえで、`url` を保存版のURLにし、元のURLを `archived_from` に書きます。サイトには「元のページは削除されたため保存版にリンクしています」と表示されます。

```json
"url": "https://warp.ndl.go.jp/web/20260305193152/https://www.mhlw.go.jp/stf/houdou/0000045845.html",
"archived_from": "https://www.mhlw.go.jp/stf/houdou/0000045845.html",
```

3. **どちらもないとき**：同じ事実を確認できる別の公式資料に差し替え、その資料で内容を確かめ直します。開けないURLをそのまま残すことはしません。

## 6. 調査状況の更新

都道府県ごとの調査状況（「該当なし」「調査したが確認できず」「未調査」の区別）は `data/survey.json` に書きます。

- `stage1`（外国人材・労働）・`stage2`（その他の分野）の `result` に、`found`（該当あり）／`none_confirmed`（公式資料で該当なしを確認）／`not_found`（調べたが確認できず）／`not_surveyed`（未調査）を書きます。
- `recheck: true` は「要再調査」の印です。調べ直したら `false` にします。
- サイト全体の最終更新日は `data/config.json` の `last_updated` と `data_as_of` を書き換えます。

## 7. 守ること（このサイトの約束）

- 存在しないMOUを作らない。公式資料で確認できたものだけを登録する
- 数字を推測で埋めない。**分からないものは `null`（未確認）にして、0にしない**
- 締結予定と締結済みを分ける（予定は `status: "planned"`）
- 発表日と締結日を分ける（`signed_date` と `announced_date`）
- 情報源には、名前・URL・確認日を必ず書く

## 8. 協定の有効性（今も効力があるか）の書き方【2026年10月に追加】

協定が今も有効かどうかは、事業が続いているか（`status`）とは**別に**書きます。サイトの件数は、初期設定では「有効確認」だけを数えます。

| 項目 | 意味 | 書き方の例 |
|---|---|---|
| `validity_state` | 有効性の区分（下の表） | `"valid_confirmed"` |
| `validity_basis` | 判定の理由（日本語1〜2文） | `"原文第5条で署名日から5年間と定めており、今日は期間内。終了の情報は見つからない。"` |
| `validity_sources` | 判定に使った出典の id | `["s1", "v1"]` |
| `validity_checked` | 有効性を確認した日 | `"2026-10-28"` |
| `effective_date` | 発効日・開始日 | `"2024-07-30"` |
| `valid_until` | **当初の**有効期限（原文に書かれたもの。分からなければ `null`） | `"2024-03-31"` |
| `valid_until_note` | 当初の期限の根拠（計算したときはその方法） | `"2019年4月1日の開始から5年間（第7項）"` |
| `renewed_until` | **更新・延長後の**有効期限（公式資料で確認できたときだけ）。判定では `valid_until` より優先 | `"2029-03-31"` |
| `renewed_until_note` | 更新後の期限の根拠 | `"入管庁の一覧の「2024年4月1日から5年間更新済み」による"` |
| `auto_renewal` | 自動更新の条項：`yes`／`no`／`not_stated`（原文に記載なし）／`unconfirmed` | `"yes"` |
| `term_text` / `renewal_text` | 有効期間・更新の条件（原文の書き方を短く） | `"署名日から5年間（第10項）"` |
| `last_renewed` | 最後に更新・延長した日 | `"2024-03-29"` |
| `ended_date` / `end_reason` | 終了日と理由（終了確認のときだけ） | |
| `successor_id` | 後継の文書のID（同じ `group_key` にする） | `"JP-27-012"` |
| `validity_research_note` | 調べたこと・確認できなかったこと | |

| `validity_state` | 画面の表示 | 使うとき |
|---|---|---|
| `valid_confirmed` | 有効確認 | (A) 原文・公式発表の有効期間内で終了の情報がない／(B) 更新・延長の事実と新しい期間が公式資料にある／(C) 自治体・省庁の最近の公式一覧が「現在締結している」「継続中」などと明示している |
| `unconfirmed` | 有効性未確認 | 上の根拠がないもの。**迷ったらこれ**。事業が続いているだけ・「自動更新」「期間の定めなし」と書いてあるだけ・期限が過ぎて更新が分からないもの |
| `ended_confirmed` | 終了確認 | 終了・失効・満了（更新しない）・後継協定への置き換えが公式資料に書かれているもの |
| `signed_not_started` | 締結済み・開始前 | 署名したが、書かれた開始日などがまだ来ていないもの |
| `planned` | 締結予定 | 予定の発表だけで、署名を確認できないもの（件数に含めない） |

- 古いというだけで「終了確認」にしない。期限が過ぎても、更新の有無が分からなければ「有効性未確認」。
- `valid_confirmed` で期限を書いた場合、その期限（`renewed_until` があればそちら）を過ぎると、サイトは自動で「有効性未確認」として数えます。更新を確認したら、`valid_until` はそのままにして `renewed_until`・`renewed_until_note`・`last_renewed` を書き足します。
- 日付は `YYYY-MM-DD`・`YYYY-MM`・`YYYY` のどれかで、**実在する日付**を書きます（`2026-02-31` などは「データ」ページの点検で誤りになります）。年月だけの期限はその月の末日（2026年2月なら28日、うるう年の2028年2月なら29日）、年だけなら12月31日まで有効として判定します。期限の当日までは有効です。
- `effective_date`（開始日）が今日より後なら、自動で「締結済み・開始前」として数えます。`ended_date` を過ぎた「有効確認」は自動で「終了確認」になります。
- 自動更新の条項（`auto_renewal: "yes"`）があるだけでは「有効確認」にしません。事業が続いている（`status: "in_progress"`）だけでも「有効確認」にしません。
- 再締結・後継の協定を見つけたら、新しい記録を足して `renewal_of` に元のID、元の記録の `successor_id` に新しいIDを書き、`group_key` を同じにします（件数は1件のまま、現在の有効性は新しい文書から判定されます）。
- 判定の確認は `node tools/test_site.mjs`（期限の境界・件数の一致などの自動テスト）と `node tools/audit_data.mjs`（取り違えやすい点の洗い出し）でもできます。件数の概要は `node tools/summary.mjs` で表示できます。

### 項目ごとの調査状況（`research`、任意）

協定ごとに、主な項目を「確認済み」「調査したが確認できず」「未調査」で区別して表示します（各協定のページの「原文・出典」の中）。書かなければ、調査の範囲から自動で決めます。自動の判定と違うときだけ、次のように書きます。

```json
"research": { "budget": "not_found", "numbers": "not_surveyed" }
```

キー：`title`（正式名称）`signed`（締結日）`effective`（発効日）`term`（有効期間）`auto`（自動更新）`end`（終了・更新）`partner`（相手）`doctype`（文書の種類）`relation`（受入れとの関連）`numbers`（人数）`status`（実施状況）`budget`（予算）`source`（出典）。値：`confirmed`／`not_found`／`not_surveyed`。

## 9. MOU以外の国際文書と、関連する国内制度【2026年10月に追加】

- EPA・交換公文・ワーキング・ホリデーの取決め・共同声明/アクションプランは `data/mous/agreements.json` に、MOUと同じ形で書きます。
- `doc_category`（文書の分類）：`mou_moc`（MOU・MOC。書かなければこれ）／`record_of_discussions`（R/D・討議議事録）／`epa_treaty`（EPA・経済連携協定）／`exchange_of_notes`（交換公文）／`bilateral_arrangement`（その他の国際取決め）／`joint_statement`（共同声明・行動計画）／`other`
  - **討議議事録（R/D、Record of Discussions）は `record_of_discussions` にします。** MOU・MOCとして数えません（「MOUのみ」の件数に入らず、「すべての国際文書」「外国人受入れに関する国際文書」で数えます）。`doc_type` に「討議議事録」「R/D」と書いたのに `mou_moc` のままだと、データ点検で誤りになります。
  - 名称に「覚書」と「R/D（RoD）」が並んで書かれているなど判断に迷うものは、原文を確かめて決め、確かめられないときは `doc_type_note` に理由を書きます（例：JP-ORG-057・067）。
  - MOU・MOCは、画面では正式名称から「MOU（了解覚書・覚書）」「MOC（協力覚書）」「協定書・合意書など」に自動で分けて表示します（名称に「協力覚書」「MOC」があればMOC、「覚書」「MOU」があればMOU）。
- 同じ協力関係の更新・後継の文書は、文書の種類が変わっても（R/Dのあとに覚書を結んだなど）同じ `group_key` にし、`renewal_of`・`successor_id` で前後をつなぎます。件数は1件で、文書の種類は最新の文書で数えます。
- CLAIRの照合（`data/clair_check.json`）で未登録のまま残す行には、`unresolved_reason`（`no_evidence` 存在を確認できない／`partner_unknown` 相手機関などの情報不足／`source_deleted` 資料が削除済み／`out_of_scope` 協定に当たらない可能性／`duplicate` 重複の疑い／`planned` 締結予定のまま）と `unresolved_note`（理由）を書きます。登録したら `site_ids` に記録のIDを入れます。件数はサイトが行から数え直します。
- `foreign_relation`（外国人の受入れとの関係）：`direct`／`indirect`／`general`／`unconfirmed`。書かなければ、分野と合意内容の文章から自動で分類します。
- `related_systems`：関係する国内制度の key（`SSW` 特定技能、`TITP` 技能実習、`ESD` 育成就労、`EPA-NCW` EPA看護・介護、`WH` ワーキング・ホリデー）。制度の説明は `data/systems.json` にあります。国内の法律や政府の方針は、海外との協定として登録しません。
- `numbers`：文書や公式資料に出てくる人数。**種類（`kind`）を必ず分けます**。

| `kind` | 意味 |
|---|---|
| `target` | 受入れ・交流の目標（法的な義務ではない） |
| `legal_cap` | 法令・取決め等に基づく上限（枠） |
| `planned_hiring` | 採用・受入れの予定人数 |
| `actual_entry` | 実際に入国した人数 |
| `actual_employed` | 実際に働いている人数 |
| `current_residents` | 現在の在留人数 |
| `incl_students_trainees_short` | 留学・研修・短期交流を含む人数 |
| `two_way_exchange` | 双方向の人的交流の人数（日本から行く人も含む） |
| `exam_passed` | 国家試験の合格者数 |

```json
"numbers": [
  { "kind": "two_way_exchange", "label": "日印双方向の人材交流の目標", "value": 500000, "unit": "人（以上）",
    "direction": "two_way", "period": "今後5年間", "definition": "原文の書き方", "sources": ["s1"], "note": "" }
]
```

- 国が全国を対象に結んだ文書（`japan_level: "national"`）は、都道府県の件数には数えません。

## 10. 締結主体の分け方と、団体・企業などのMOU【2026年10月28日に追加】

日本側・相手側の機関の**名前と種類を別々に**記録します。相手側の種類は `partner_type`（2の表）、日本側の種類は `japan_org_type` です。

| `japan_level`（件数の区分） | `japan_org_type`（日本側の種別） | 画面の表示 |
|---|---|---|
| `national` | `national_gov` | 日本政府・省庁 |
| `prefecture` | `prefecture` | 都道府県（県の教育委員会・県立学校を含む） |
| `municipality` | `municipality` | 政令指定都市・市区町村 |
| `organization` | `public_body` | 公的機関・独立行政法人等（JICA・JETRO・外国人技能実習機構など） |
| `organization` | `company` | 民間企業 |
| `organization` | `association` | 財団法人・社団法人・業界団体 |
| `organization` | `university` | 大学・教育機関 |

- 国・都道府県・市区町村は `japan_org_type` を省略できます（区分から自動で決まります）。**団体・企業など（`organization`）は必ず書きます。**
- 「政府間」「自治体間」「公的機関間」「官民間」「団体間」の区別は、日本側と相手側の種類から自動で決まります（検索の絞り込みに使います）。
- **団体・企業などの協定は、日本政府や都道府県が直接締結した件数に含めません。**`pref_code` は `null` にします。本部・会社の所在地を理由に都道府県を入れると、データ点検で「誤り」になります。
- 協定に関連する事業が特定の地域で行われたと公式資料で確認できたときだけ、`related_regions` に書きます。都道府県のページと地図の選択欄に「この地域に関連する事業」として、締結した協定とは分けて表示されます（件数には入りません）。

```json
"related_regions": [
  { "pref_code": "04", "text": "2025年度に県内企業で研修生を受入れ", "sources": ["s3"] }
]
```

- 首脳会談の機会に首相官邸で交換された文書のように、政府が立ち会っただけのものは、`ceremony_note` に事実を書きます（例：「首相官邸で両首相の立会いのもと交換。日本政府は当事者ではない」）。政府の協定としては数えません。
- 市区町村のMOUは `municipality_code`（全国地方公共団体コード6桁）と `municipality_name`（市区町村名）を入れ、`pref_code` はその市区町村がある都道府県にします。県の件数とは別に数えます。ID は `JP-CITY-141003-001` の形です。
- 団体などのID は `JP-ORG-001` の形です。

## 11. サイト内検索のしくみ【2026年10月28日に追加】

- 検索は `assets/js/search.js` で行います。スペースで区切った言葉は**すべてを含む**協定を探します（AND検索）。
- 表記ゆれ（CLAIR／クレア／自治体国際化協会 など）は `search.js` の `SYNONYMS` に1行足すと、どれで検索しても同じ結果になります。国名・都道府県名の別名は `countries.json` の `aliases`、`prefectures.json` の `en` から自動で使います。
- 検索する項目（協定名・本文・締結機関・署名者・担当省庁・関連団体・地域・相手国・文書の種類・分野・制度・事業・人数・予算・出典など）は `search.js` の `groupIndex` に並んでいます。新しい項目をデータに足したときは、ここにも足してください。
- 手元で検索を試すには、mou-map フォルダで次を実行します（どの項目に一致したかも表示されます）。

```bash
node tools/search.mjs "宮城県 ベトナム" "NAGOMi VAMAS"
```
